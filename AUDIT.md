## Локальная очередь и захват · 0.3.0

Проверки выполнены на этом Windows-ПК без создания нового ролика. 16 кадров архивного V2: старые скриншоты 1.369 с суммарно, прямой Canvas 0.865 с (примерно на 37% меньше времени захвата). PNG на 0, 1.5, 5.88, 8 и 13.9 с совпали по RGB пиксель в пиксель. Это не замер полного MP4 и не прогноз времени Emergent. Маркер Canvas не добавлялся в архивный пример; его код сохранён. Кадр 5.88 с визуально проверен: остаток старого титра у левого края воспроизведён и отмечен в HANDOFF.

Захваченные кадры реально кодировались H.264 в null-вывод для проверки входного потока, файл нового видео не создавался. Проверены отказ небезопасного Canvas при CSS-фильтре и переход auto к скриншотам. Проверены упаковка/распаковка исходников и общих шрифтов с SHA-256, отказ путей с выходом из задания, OS-скриптов, повторных ZIP-имён и изменённого ассета. Проверены два архива из разных аккаунтов с одними данными: одно задание, исходные скачанные файлы сохранены; блокировка второго обработчика работает.

Дополнительно: фактический render_scene.py в режиме только контрольных кадров отработал на распакованном отдельном корне сцены. Скрытый запуск на Windows вернул управление терминалу, повторный запуск распознал работающую очередь, остановка завершила её. Исходная проблема PowerShell с перенаправлением потоков исправлена запуском через Python с отдельными файлами журналов. Проверка намеренной ошибки дочернего рендера подтвердила status=error, без ложного done и автоматического повторения. Полный заказанный фильм этой проверкой не создавался.

Файловая ссылка из конкретного аккаунта Emergent и полный MP4 новой сцены в этой схеме ещё не проверены. Первый архив должен подготовить облачный агент и проверить его скачивание; локальные тесты этого не заменяют. Нативный After Effects остаётся непроверенным.
